# 用 MD 仓的 ImmortalWrt 25.12 编译树出 apk —— 操作手册

> 目标：拿到 `luci-app-dns-switch-*.apk`（aarch64_generic / apk-tools 3），能在 R68S 上
> `apk add --allow-untrusted` 装上，并顺带把"出厂预装"这条线做通。
>
> 前置事实（均已核实，2026-11-11）：
>
> | 项 | 事实 |
> |---|---|
> | 仓库 | `2286927/ImmortalWrt-MultiDevice`（**public**，main 分支，21 个 workflow） |
> | 目标 workflow | `.github/workflows/ImmortalWrt-25.12-r68s.yml`（active） |
> | 目标架构 | `CONFIG_TARGET_ARCH_PACKAGES="aarch64_generic"`，`CONFIG_USE_APK=y` |
> | 配置文件 | `config/r68s-25.12.config`（5624 个 CONFIG_PACKAGE，**不含**本包） |
> | 分支 | `feat/dns-switch-factory` 已接 90%：diy-part2 注入块、payload、inject.sh 都在 |
> | 分支缺什么 | ① `verify.sh` 是旧版（192 行/23 断言，会误报 crontabs）② payload 里 `dns-switch` 是旧版（md5 `4462fd42`，仓库现版 `5a9365c0`）③ 配置没有本包 ④ workflow 不收 `bin/packages` |
> | 上次失败 | run 42780835113 红在"加载配置"步的注入断言：`✗ 未整份覆盖 etc/crontabs/root`（本地已修，见下） |
> | Actions 计费 | public 仓库 → 标准 runner **不计费**，一次全量约 40–60 分钟 |
>
> 结论：不需要新建 workflow，也不用碰 SDK；**在现有 r68s 构建线里加 4 处改动**即可同时得到固件和 apk。

## 一、先想清楚：两条线路只能选一条

同一个包有两种进固件的方式，**不能同时用**，否则同一批文件被装两遍、`apk` 记录与 overlay 打架：

| 线路 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A · 包安装线（推荐）** | 包源进 `package/`，config 选 `=y` | 固件里能看到、能 `apk del`、卸载走 prerm（已实测不断网）；顺手产出 apk | 首次 build 多编一个包（几分钟） |
| B · 文件覆盖线（分支现状） | payload 进 `files/` 覆盖层 | 简单，不依赖包管理器 | `apk` 里看不到、不能卸载、与"做成 OpenWrt 软件包"的目标相悖 |

下面按 **A 线**写。B 线的 `diy-part2.sh` 注入块（第 555–572 行）建议**注释掉**，否则两套文件同时落地。

## 二、五处改动（全部在网页上做）

### 改动 1 · 上传包源到仓库

目标目录：`scripts/common/luci-app-dns-switch/`

上传这 8 个文件（保持目录结构，网页 Upload files 支持拖文件夹）：

```
scripts/common/luci-app-dns-switch/
├── Makefile
├── root/usr/bin/dns-switch
├── root/etc/init.d/dns-switch
├── root/etc/uci-defaults/99-dns-switch
├── root/etc/config/dns_switch
├── root/usr/share/luci/menu.d/luci-app-dns-switch.json
├── root/usr/share/rpcd/acl.d/luci-app-dns-switch.json
└── htdocs/luci-static/resources/view/dns_switch/overview.js
```

本地源：`luci-app-dns-switch/luci-app-dns-switch/`（md5 见 `MANIFEST.md`）。
**注意**：GitHub 网页上传会把文件存成 644，执行位靠改动 3 里的 `chmod` 补，不要漏。

> 不想把源码放进 public 仓？见文末「B 方案：源码留在私有仓」。

### 改动 2 · 更新出厂断言脚本（否则一跑就红）

用本地新版覆盖：`scripts/common/dns-switch/verify.sh`
（本地：`dns-switch-20261109/factory/scripts/common/dns-switch/verify.sh`，209 行 / 39 项断言）

**为什么要改**：分支上那份只查 `$DST`（整棵 `files/`），而 `diy-part2` 自己会往
`files/etc/crontabs/root` 追加 autoupdate 行，于是断言必然误报——上次构建就是这么红的。
新版改成只查 `$SRC`（payload 自己这 6 个文件），并补了 L 组（drill/bundle/timeline 等）。

同时把 `scripts/common/dns-switch/payload/` 下的 6 个文件也换成新版
（分支上的 `dns-switch` 是 `4462fd42`，比仓库现版旧，缺 P0-6/P1 的全部命令）。

### 改动 3 · 在 `scripts/25.12/diy-part2.sh` 里落地包源

在文件末尾那句 `echo -e "\n===== diy-part2.sh（25.12）执行结束 ====="` **之前**插入
`diy-part2-pkg-snippet.sh` 的内容（见本目录同名文件）。

它做三件事：判定 `DEVICE_MODEL=r68s` → 把包源拷进 `package/luci-app-dns-switch/` →
补执行位 + 去 CRLF。其余 17 条编译线进不了这个 if。

### 改动 4 · 配置里选中这个包

把 `config-line.conf` 里那一行追加到 `config/r68s-25.12.config` 末尾：

```
CONFIG_PACKAGE_luci-app-dns-switch=y
```

选中后：固件自带该包（出厂即装好），且构建过程中会把 apk 产物吐到
`openwrt/bin/packages/aarch64_generic/base/`。

### 改动 5 · workflow 收集 apk

`.github/workflows/ImmortalWrt-25.12-r68s.yml` 里，在「上传 bin」那一步**之前**插入
`apk-collect-step.yml` 的内容（两步：收集 + 上传）。

**为什么现有 `upload_packages_dir` 不够**：它上传的是 `bin/targets/<target>/packages`
（目标平台专用包），本包是 `PKGARCH:=all`，产物落在 `bin/packages/<arch>/base/`，
两者不是同一个目录。直接用那个开关，跑完 40 分钟会发现 artifacts 里没有它。

## 三、跑一次

1. 打开 Actions → `ImmortalWrt-25.12-R68S` → Run workflow
   - 分支：选你改动的分支（或先合并回 main）
   - `upload_bin_dir`：按需；`upload_packages_dir`：**不用勾**（我们用自己的 artifact）
2. 预期 40–60 分钟；成功标志：
   - 日志里出现 `>>> dns-switch 包源已就位`
   - 日志里出现 `>>> …/luci-app-dns-switch-1.0.0-r1.apk`
   - Artifacts 里有 `luci-app-dns-switch-apk-r68s<日期>`
3. **失败先看两处**：
   - 「加载配置」步 → 注入断言红 → 改动 2 没生效
   - 「编译」步 → `No package 'luci-app-dns-switch' found` → 改动 3/4 的路径或 `DEVICE_MODEL` 判定不对

## 四、装到设备验收（约 10 分钟）

```sh
# 1. 传上去
scp luci-app-dns-switch-*.apk root@172.16.1.1:/tmp/
ssh root@172.16.1.1

# 2. 装
apk add --allow-untrusted /tmp/luci-app-dns-switch-*.apk
apk info -e luci-app-dns-switch      # 应打印包名

# 3. 跑
dns-switch status                    # 有输出 = 执行位对
/etc/init.d/dns-switch status        # running

# 4. 页面
#    服务 → DNS 网关切换：状态卡、参数、主按钮都在

# 5. 卸载（最关键）
apk del luci-app-dns-switch
nslookup www.baidu.com 127.0.0.1     # 仍要能解析（prerm 把 DNS 还原了）
nft list chain inet fw4 dns_hijack   # 应报不存在
```

第 5 条是这轮唯一没被真实验证过的动作（本轮只做了文件级模拟，D08 通过）；
`apk` 的 prerm 触发时机与文件删除顺序，只有真装真卸才算数。

## 五、B 方案：源码留在私有仓

如果暂时不想把 `luci-app-dns-switch` 转公开：

1. 仓库 Settings → Secrets and variables → Actions → New repository secret
   名称 `DNSSWITCH_TOKEN`，值用 fine-grained PAT（只给 `2286927/luci-app-dns-switch` 的 **Contents: Read**）
2. workflow 的 `env:` 加一行 `DNSSWITCH_TOKEN: ${{ secrets.DNSSWITCH_TOKEN }}`
3. diy-part2 里改用 `diy-part2-pkg-snippet-private.sh` 的写法（`git clone` + `x-access-token`）

代价：多一个 secret、多一处失败面；收益：源码不公开。若按 `发布计划.md` 本来就打算转公开，
不建议走这条。

## 六、风险与回滚

| 风险 | 概率 | 处理 |
|---|---|---|
| 注入断言仍红 | 低（本地已 39/39） | 看断言输出逐条对；必要时把 `inject.sh` 的 `verify.sh` 调用临时注释，但**不建议**——断言是唯一能挡住"包是残的"的东西 |
| `make` 因新包报错 | 低（纯 shell + JSON + JS，无编译步骤） | 日志里搜 `luci-app-dns-switch`；`LUCI_DEPENDS` 只依赖 luci-base + nftables，都在 config 里 |
| 固件体积变大 | 忽略（< 100 KB） | — |
| 装上去菜单不出现 | 中（ACL/菜单路径） | 先 `rm -f /tmp/luci-indexcache`，再看 `ubus list | grep dns-switch` |
| 想撤回 | — | revert 那 5 处改动；固件与包都是构建产物，不影响设备 |

## 七、一句话

**不用借 SDK，也不用新建仓库**：MD 仓的 r68s 构建线本来就在编 LuCI 包，
把"包源 + 配置一行 + 收产物一步"接进去，40 分钟后固件和 apk 一起出来；
真正要小心的只有两件事——**别让旧版 verify.sh 拦住构建**，**别让 files/ 覆盖和包安装同时存在**。
