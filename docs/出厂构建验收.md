## 三、五轮排障时间线（决策留痕）

| 轮次 | run / head | 结果 | 定位到的下一个卡点 |
|---|---|---|---|
| 1 | `43555643663` / `ebc74e21` | failure | 内核补丁失配已修好，首次走到 package 阶段，卡 `rust [host]` |
| 2 | `43561934296` / `64bc40d4` | failure | 禁用 passwall 两个 Rust 组件无效，仍 `rust [host]` |
| 3 | `43579188130` / `7468d1c` | failure | 摘除 rust feed 后 `rust [host]` 消失，但 dufs 失去依赖而失败 |
| 4 | `43586189962` / `64f4feb` | failure | V=s 诊断确诊 `curl (22) 404 ×4` → `ERROR: failed to download llvm from ci` |
| 5 | `43590895684` / `5dfe323` | **success** | 关闭 `llvm.download-ci-llvm`，rust 改用源码自带 LLVM 编译 |

**根因链**：dufs（Rust 编写、实机在用）声明 `PKG_BUILD_DEPENDS:=rust/host`
→ 拉起 rust `1.96.0` host 工具包 → 上游 Makefile 写死从 CI 下载预编译 LLVM，
该 commit 的制品已 404 → 编译失败。
上一轮 10 连红的内核补丁失配是另一条独立问题，已通过整批移除
`patches-6.12/041-*` 显示子系统 backport 解决（四轮零 `Patch failed`）。

## 四、最终生效的 MD 仓改动

1. `scripts/25.12/diy-part2.sh`：仅 `DEVICE_MODEL=r68s` 时
   - 移除 `patches-6.12/041-*.patch`（上游补丁失配临时规避）
   - `git clone --branch v1.0.0` 本仓 → `package/luci-app-dns-switch/`，补执行位、写 `CONFIG_PACKAGE_...=y`
   - 把 `feeds/packages/lang/rust/Makefile` 的 `llvm.download-ci-llvm=true` 改为 `false`
   - 三段均严格限定 r68s，共用该脚本的其余 8 条 25.12 线不受影响
2. `.github/workflows/ImmortalWrt-25.12-r68s.yml`：编译失败分支保留 `V=s` 诊断（成功时不执行）。
3. MD 仓 `main` 已删除 `feat/dns-switch-factory`、`feat/dns-switch-pkg` 两个开发分支，
   **不存放本包任何源码**，只按 tag 引用。
