## 四、发现的问题

### F1（高）守护进程把参数缓存到启动那一刻，改完参数会被旧值覆盖

**现象**：在页面/SSH 改了 `fallback_dns`（172.16.5.5 → 172.16.9.9）并 `dns-switch on` 生效后，只要 daemon 跑一次"漂移重建"，下发就被改回 **旧值**：

```
配置值  fallback_dns = 172.16.9.9
手工 on 后 opt6      = 6,172.16.1.2,172.16.9.9     ← 正确
删掉上游触发漂移自愈（55s 内）后：
  logread: DHCP 下发 DNS → 6,172.16.1.2,172.16.5.5  ← 用回了旧参数
  applied_sig            = ...|172.16.5.5|...        ← 而且把旧值记成"已应用"
```

**根因**：`dns-switch` 在进程启动时把配置读进全局变量（第 62–70 行 `FB/ADH/DOT853/MAC_CFG/UPSTREAM_MODE`），而 daemon 是 `while :; do do_tick; sleep 55; done` 的常驻循环，**整个生命周期只读一次**。`do_tick` 里的漂移重建、`tier_failover`/`tier_on` 都用这份缓存。

**危害**：用户改完参数（页面保存当次是好的），之后任何一次自愈/降级/回切都会把配置悄悄改回旧值；因为 `applied_sig` 写的是旧值，签名比对还认为"已应用"，不会自我纠正——典型的静默错位。

**建议修法**：`do_tick` 开头（或在 `do_on`/`tier_*` 之前）重新 `FB=$(s_opt fallback_dns)` 等赋值，抽一个 `reload_cfg()` 即可；改完用本轮脚本 `exp_f1.py` 复跑即可验证。

> 复现脚本：`test-run-20261111/exp_f1.py`（约 40 秒，会把当时的 logread 证据打印出来）

### F2（中）快照回滚不还原 dns_switch 参数，回滚后又被当前参数覆盖

`snap_save` 明明存了 `dns_switch.uci`，`snap_restore` 却只还原 `/etc/config/dhcp`、nft 片段和 `mode`，然后用**当前**参数再跑一次 `do_on`。结果：

```
改前 fallback_dns=172.16.5.5 → 快照 → 改成 172.16.9.9 → on
回滚该快照后：opt6 仍是 6,172.16.1.2,172.16.9.9（不是快照里的 5.5）
```

也就是说，**"改坏参数"这类故障回滚无效**，只有 `/etc/config/dhcp` 被外部改坏时回滚才有意义。建议 `snap_restore` 把 `dns_switch.uci` 里 `settings` 段一并还原（或用 `uci import`），再做 `do_on`。

### F3（低）空值 option 建不出来，"补齐空键"是空写

`99-dns-switch` 里 `uci set dns_switch.settings.$k=` 想给 `fallback_dns6`/`isp_list4`/`isp_list6`/`adh_mac` 建空键，但 `uci commit` 会把空值 option 丢掉（实测：`uci set x='' && uci commit` 后 `uci get` 返回 rc=1）。所以配置里永远只有 10–11 个键，而不是 14 个。

功能上无影响（`s_opt` 本来就把"不存在"当空串），但注释里"空字符串也是合法值"的说法与实际不符，且会让"配置完整性检查"这类断言失真。建议：要么删掉这四行，要么改成 `uci set x=''` 后不 commit（无意义）——最干净是承认"空键不存在"并在文档里写明。

### F4（已解决）25.12 装不上包 —— 已用 25.12 SDK 出 apk 并在真机装通

原判断是三条约束叠加（本机无编译树、设备无 `mkpkg`、CI 只出 ipk）。放开"网页改 workflow"后，
在包仓新增了 `build-apk-25.12.yml`，用 ImmortalWrt 25.12 rockchip/armv8 SDK 出 `.apk`，
