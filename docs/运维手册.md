# 运维手册（r68s / 172.16.1.1）

> 唯一实机基准：r68s `172.16.1.1`，ImmortalWrt 25.12-SNAPSHOT，apk 包管理。
> 代码以本仓 tag 为准，见 `SOURCE_OF_TRUTH.md`。

## 一、装机与卸载

```sh
apk add --allow-untrusted luci-app-dns-switch_1.0.0-r1.apk
apk info -e luci-app-dns-switch
dns-switch status                 # 有输出 = 执行位正确
/etc/init.d/dns-switch status     # running
```

卸载走 `prerm` 先还原 DNS 再删文件，**不会卸个软件把网卸断**：

```sh
apk del luci-app-dns-switch
nslookup www.baidu.com 127.0.0.1        # 仍要能解析
nft list chain inet fw4 dns_hijack      # 应报不存在
```

`/etc/config/dns_switch` 属于 `conffiles`，卸载保留用户配置。

**覆盖安装必须重启守护**：`apk add` 只换磁盘文件，正在运行的 daemon 仍是旧二进制。验证 daemon 行为前先 `/etc/init.d/dns-switch restart`，否则会把“验证方法错”误判成“修复无效”（2026-11-12 真实踩过一次）。

## 二、sysupgrade 保留清单

`sysupgrade` 会丢页面 / 菜单 / ACL / 自启链接，`/etc/sysupgrade.conf` 需含以下条目（2026-11-14 已补，幂等）：

```
/usr/bin/dns-switch
/etc/init.d/dns-switch
/etc/config/dns_switch
/www/luci-static/resources/view/dns_switch
/usr/share/luci/menu.d/luci-app-dns-switch.json
/usr/share/rpcd/acl.d/luci-app-dns-switch.json
/etc/rc.d/S99dns-switch
/etc/rc.d/K10dns-switch
```

- `/etc/config/` 由 `keep.d/base-files` 整份保留，目录条目递归生效。
- 校验用 `sysupgrade -l | grep dns`（权威清单）；**不要用 `sysupgrade -b`**，在 r68s 上会卡死。
- 重装 `luci-app-dns-switch_1.0.0-r1_r38263.apk` 可恢复且配置零丢失，装完即 `mode=on`。

## 三、升级后的已知残留

| 现象 | 影响 | 处置 |
|---|---|---|
| `apk` 数据库记录丢失（`/lib/apk/db`） | 升级后 `apk list` 查不到该包、`apk del` 卸不掉，但功能与 LuCI 入口完整 | 重装一次 apk 即可 |
| `/etc/config/dns_switch.apk-new`（703 B，默认 `mode=off`） | 无害，但在保留清单里 | 建议清理 |
| post-install 打印 `uci: Parse error (invalid command) at line 5` | 被 Makefile 的 `\|\| true` 兜住，功能无影响 | 记入 v1.0.1 修复 |
| `status` 的「ether 豁免: N 条」读磁盘片段，重建窗口内显示 0 | 实际规则正确 | R-1，v1.1 改为读 `nft list chain` |

## 四、日常验证命令

```sh
dns-switch status                  # mode / effective / 53 端口 / 劫持链
dns-switch on                      # 切到 ADH（含探测与自检）
dns-switch off                     # 切回运营商
dns-switch drill                   # 演练降级与回切，终态应仍为 on
dns-switch rescue                  # 逃生：不依赖守护、LuCI、DNS，复位到原生
dns-switch timeline                # 最近的切换 / 降级 / 漂移 / 冲突
dns-switch bundle                  # 生成诊断包
dns-switch snapshot list|diff|restore X
```

`rescue` 是唯一一条故意零依赖的命令，只负责 DNS 层；接口层故障（netifd 卡死）归 netguard 管，不得与它抢 reboot 决策。

## 五、出厂态

刷完机就是一台普通路由器：原生 DNS、能上网，`mode=off`、不预置 `20-dns-hijack.nft`。ADH 就绪后在「服务 → DNS 网关切换」点一下才切过去。守护服务需 `enable` + `start` 常驻，否则页面点「启用」的 procd reload 触发器没有实例可触发。

## 六、适用前提

- fw4 / nftables（OpenWrt 22.03+）；fw3 上装了只会“看着成功、其实不生效”
- busybox 带 `flock` applet
- `curl` 是精度增强而非硬依赖，缺它只降探测精度、不阻断也不降级

设备上**没有 `diff` / `comm`**，快照比对用 `cmp` + `awk`；改完 LuCI 页面验证前必须 Ctrl+F5（LuCI 静态资源的 `?v=` 是全局版本号，不是文件 mtime）。
